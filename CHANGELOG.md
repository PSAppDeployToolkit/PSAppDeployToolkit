# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Version headings are the SemVer version. The git tag for a version is `v` plus that version exactly, enforced by CI. Tags up to and including `v0.8.19-pre` used a `-pre` suffix that did not match the `-preview` version they shipped, which is why some links below point at the releases page instead of a comparison. From `0.9.0-pre` the suffix is `pre`, so the tag and the version are the same string.

## [0.9.0-pre] - Unreleased

This is the last preview before 1.0 and it carries the whole 1.0 readiness pass, breaking changes included. The public CLR surface and the public XAML resource key set take the shape they will freeze in: `Microsoft.CodeAnalysis.PublicApiAnalyzers` enforces the CLR half and a key inventory test enforces the XAML half, so a change to either is a build failure rather than a review miss. The freeze itself starts at 1.0, when minor releases become additive only and removals or signature changes wait for a major release. Until then this section can still move, and any further break lands in another pre-1.0 preview. Every breaking change below is written up in [docs/migration-guide.md](https://github.com/sintaxasn/Fluence.Wpf/blob/main/docs/migration-guide.md).

### Added

- `AccentAcrylicBackgroundFillColorBase` and `AccentAcrylicBackgroundFillColorDefault` (and their brush twins) are published, the accent acrylic fallbacks WinUI builds from the accent ramp (`AcrylicBrush_themeresources.xaml`: Dark2 and Dark1 in dark, Light3 for both in light). The Colors page gains the Accent Acrylic Background group that needed them.
- `ComboBoxItemCornerRadius` (3) joins `ControlCornerRadius`, `OverlayCornerRadius` and `PopupCornerRadius` as a published corner radius key, the one WinUI keeps distinct from `ControlCornerRadius` for the drop-down item, so an application that retunes corner radii can reach the `ComboBoxItem` through a supported key.
- `SelectorBar` and `SelectorBarItem`, the WinUI 3 `SelectorBar` family: a row of peer destinations with an accent pill under the selected label. Items carry `Text` and an optional `Icon`, the bar is always single-select, and the pill plays WinUI's own reveal (the 4 px rest pill scaled to four times its width over 167 ms on the `0,0,0,1` spline, skipped when motion is off). `SelectorBarItemAutomationPeer` reports the item label, which lives on `Text` rather than the unused inherited content.
- `SlideNavigationPresenter` and `SlideNavigationTransitionEffect`, a content host that plays WinUI's horizontal slide navigation transition on every content change: the outgoing content fades out as it slides 150 px away over 150 ms, and the incoming content enters 200 px out and settles over a further 300 ms, on WinUI's own key splines (`dxaml/phone/lib/ThemeTransitions.cpp`). WinUI's third effect, `FromBottom`, is not ported; the gap is recorded in `docs/winui-parity.md`, and because the enumeration keeps WinUI's numbers the presenter's `TransitionEffect` rejects `FromBottom`'s 0, which is also `default`, with an `ArgumentException` rather than playing a horizontal effect for it.
- Demo: the Colors page is rebuilt from the WinUI 3 Gallery Color page. Six sections (Text, Fill, Stroke, Background, Signal, High Contrast) each pair a `ColorPageExample` card with rows of `ColorTile` swatches painted in the brush they name, in the Gallery's order, wording and column counts, with a copy button per tile. Three platform deviations are documented in the page: WPF has no per-element backdrop, so Acrylic and Mica tiles show their fallback brushes; the tile-less Mica Background group is omitted for the same reason; and High Contrast shows the live `SystemColor*` aliases instead of four hard-coded palettes. The `ThemeDictionary` sample that lived at the foot of the old page is gone from Colors (it is not part of the Gallery page); the Home page hero and `docs/theming.md` still demonstrate it. Every size on the page comes from new `DemoColor*` tokens in `DemoSharedStyles.xaml`.
- Demo: `GalleryPageHeader` is a shared gallery page header modelled on the WinUI 3 Gallery's `PageHeader`, with a title, a Documentation link, a theme toggle and a Favorite toggle, adopted by 17 of the 18 gallery pages.
- `ContentDialogOpenedEventArgs`, `ContentDialogClosedEventArgs` (carrying `Result`), `InfoBarClosedEventArgs` and `TeachingTipClosedEventArgs` (both carrying `Reason`), the args classes for the four events that had none.
- `InfoBarCloseReason` (`CloseButton`, `Programmatic`) and `TeachingTipCloseReason` (`CloseButton`, `LightDismiss`, `Programmatic`), mirroring WinUI.
- `InfoBar.Opened` and `InfoBarOpenedEventArgs`, the last of WinUI's `InfoBar` events that Fluence did not raise. It fires on the `IsOpen` transition, and a `Closing` handler that cancels does not produce one, because the revert is not a fresh open.
- `InfoBadge.GetStyleGlyph(InfoBadgeStyle)`, which returns the Segoe Fluent glyph WinUI puts on that severity's icon badge, on the `InfoBar.GetSeverityGlyph` precedent. It is opt-in: WinUI ships a dot, a value and an icon style per severity, and Fluence has one `BadgeStyle` property, so supplying the glyph automatically would take the dot and value forms away.
- Five `InfoBadge*ForegroundBrush` keys, one per `InfoBadgeStyle`, which is how WinUI keys the badge's foreground. Outside high contrast all five are `TextOnAccentFillColorPrimary`, as before; in high contrast each follows its own plate, so the Attention badge takes the highlight text colour and the other four take the window colour instead of a fixed black numeral that could land on a black plate.
- `InfoBadge.CornerRadius`, which the badge keeps at half its own height unless a consumer pins it.
- `InfoBar.CloseButtonClick`, `InfoBar.CloseButtonCommand`, `InfoBar.CloseButtonCommandParameter` and `InfoBar.CloseButtonStyle`, the four members WinUI's own `InfoBar` carries for its close button. The click and the command run before the close pipeline, so a cancel still belongs in `Closing`.
- `InfoBarClosingEventArgs.Reason`, so `Closing` and `Closed` agree on why the bar is closing.
- `TitleBarAutomationPeer`, `InfoBadgeAutomationPeer` and `FlyoutPresenterAutomationPeer`. All three controls previously reported to a screen reader as a bare `FrameworkElement` with no control type; `InfoBadge` had no accessible representation of its count at all.
- `Expander.HeaderBackground`, the brush that fills the header tier. WinUI keys the two tiers separately, giving the header `ExpanderHeaderBackground` and the content the control's own `Background` (`Expander.xaml:111,114`); this is the header half of that pair, so either tier can be recoloured without retemplating. It defaults to the card default fill, so an expander that sets neither renders as it always has.
- `Expander.TopCornerRadiusFilter` and `Expander.BottomCornerRadiusFilter`, public `IValueConverter` fields that replace the two corner-radius converters internalised below for template use via `x:Static`.
- The resource keys `ContentControlThemeFontFamily` and `ApplicationPageBackgroundThemeBrush`, WinUI's names for `FluentFontFamily` and `ApplicationBackgroundBrush`. Both pairs ship and both original names are supported for the life of 1.x.
- SourceLink, portable PDBs and a `.snupkg` symbol package, so a consumer can step into library sources from a debugger.
- `Microsoft.CodeAnalysis.PublicApiAnalyzers` with one `PublicAPI.Shipped.txt` baseline shared by the three target frameworks (the surface is identical across them; a framework-specific member would fail the analyzer for that framework, which is the moment to split the file), and `ThemeParityTests.PublicKeyInventory_MatchesFrozenSetAsync` with `Theming/golden/PublicKeys.txt`, which together freeze the public surface mechanically.
- A CI guard that fails a `v*` tag whose version does not match the tree, release notes taken from this file rather than from the commit list, and an automated NuGet push on a version tag.

### Changed

- Regression coverage adds 17 .NET cases per full target framework for homepage navigation/reflow, native-handle theme watching, footer automation, tree removal/reset, smooth scrolling and dialog ownership. One homepage method is renamed to reflect rendered social-link coverage; no case is removed. The reviewer follow-up adds seven further cases for collapsed data-bound tree selection, safe collection additions, input-pressure scrolling and hosted Colors/Data scrolling. Discovery baselines are now 1375 on net472 and 1378 on net10, with CI floors of 1374 and 1375 after screenshot generators are excluded.
- PowerShell review hardens apostrophe-path imports, result-name collisions, choice defaults, callback output and failed-window cleanup, progress closure/reimport, explicit false switches and Escape dismissal. Core hosts now fail clearly below PowerShell 7.4; foreign WPF dispatchers without PowerShell execution context are explicitly unsupported. The module ships its BSD license. Nineteen focused logic and runspace-ownership regressions plus three UI lifetime/keyboard regressions bring the Pester suite from 162 to 184 cases. The reviewer follow-up adds 28 logic cases covering secure passwords, safe result display, package imports, version agreement and missing-provider rejection, for 212 cases in total.
- PowerShell Password prompts return `SecureString` by default; `-AsPlainText` explicitly opts into string results. Secure password validators receive `SecureString`, and pattern validation requires the plaintext opt-in. `Fluence.DialogResult` has a default format view that omits all user input, including arbitrarily named password fields. See the migration guide for the pre-1.0 behavior change.
- Module function discovery accepts literal installation paths and fails clearly for incomplete packages. Format definitions live under `Formats/`; pack-image URI documentation now distinguishes early validation from resource resolution on the UI thread.
- PowerShell testing and packaging run in a separate CI job using the built library artifacts. Exact analyzer/test-tool versions are pinned, provider setup is explicit, and module packaging refuses a manifest/tree version mismatch before changing staged files. Library artifacts and tagged NuGet releases no longer depend on PowerShell tooling availability.
- Collapsed data-bound parents preserve their checked state while they still have unrealized children. Unrelated unchecked additions avoid rebuilding the selection list, while selected additions still reconcile it. Scroll updates run after layout at Loaded priority so queued input cannot indefinitely delay them; the external-offset queue protections remain covered.
- Gallery Home now leads with a larger responsive, theme-aware Fluence.WPF logo, native GitHub and LinkedIn icon links, and a compact control catalog. The live preview section is removed; keyboard navigation, responsive card columns and theme swapping remain covered by hosted tests.
- `ContentDialog` permits one active dialog per owner window and reports a clear error if another is requested. Reservations are released on close, owner shutdown and failed opening, so normal input cannot be trapped between two modal overlays.
- `SystemThemeWatcher` attaches when a native window handle already exists, including the `FluenceWindow` source-initialization path. Footer navigation automation now supports selection and invocation through the same owner as main items.
- Removing or resetting tree items reconciles the live multiple-selection list. Smooth scrolling resumes from the current offset after scrollbar or programmatic movement. The existing limitation for cascading into unrealized data-bound branches is documented in `KNOWN_ISSUES.md`.
- PowerShell performs bounded terminal cleanup of its owned secondary dispatcher when the primary ConsoleHost exits. Child runspaces and custom hosts retain dispatcher ownership. The standalone test runner checks for leaked windows and shuts down its inline dispatcher before ending the owning thread; process shutdown failures are no longer treated as passing runs.
- CI exercises the PowerShell MTA logic path separately and installs testing dependencies for each PowerShell edition. The .NET Framework library artifact includes its dependency DLLs, so the download can be consumed outside a NuGet project.

- `Expander` takes WinUI's box model. The header carries `ExpanderHeaderPadding` 16,0,0,0 and gets its height from `ExpanderMinHeight` 48 rather than from 11 dip of vertical padding; `MinHeight` and `Padding` are set on the control and template-bound into both tiers, so `Padding` now insets the content tier (default `ExpanderContentPadding` 16) instead of being ignored. `Background` paints the content tier, which is where WinUI puts it, and the header takes the new `HeaderBackground` instead; a consumer who set `Background` to colour the header now colours the content, and moves that value to `HeaderBackground` to keep the old result.
- Demo: `DemoSampleControl` hosts the stock `Expander` for its source section rather than a copy of the control's template, configured as the WinUI Gallery configures its own (`ControlExample.xaml`): no padding, stretched, card secondary fill and bottom-only corners. The two demo-local styles that duplicated the header, the chevron and the expand slide are gone.
- Demo: the gallery page scrollbar rides the window frame at the far right of the navigation view's content, which is where the WinUI 3 Gallery puts its own: the Gallery's page `ScrollViewer` sits outside the page content margin, so the rail is clear of the cards rather than inset from them. The scroll host gives the whole right page margin back to reach the frame and the scrolling content pays the same amount again, so the cards still end where the page title does. The Colors page follows suit, one scroll host per section inside its `SlideNavigationPresenter`, so the rail sits in the same place on every page.
- Demo: every gallery page sets the theme text brush on its root. WPF's `Page` resolves its own `Foreground` from `SystemColors` instead of inheriting it, so page text rendered black on the dark theme until a later theme change re-resolved it.
- Demo: the Colors page content stretches to the shell width, which matters most in Top pane display mode where the pane hands its width back to the content. Tile labels wrap when the column is narrow enough, as the Gallery does at its own width.
- Demo: the Colors page High Contrast section shows the four contrast themes Windows ships (Aquatic, Desert, Dusk, Night Sky) as fixed palettes under the live system-colour row, as the Gallery's own High Contrast section does. `ColorTile` now accepts a literal colour for those palette tiles; live tiles are unchanged.
- Demo: the Colors page scroll host moved inside the `SlideNavigationPresenter`, one per section, so the scrollbar belongs to the section on screen and travels with it through the slide. Each section's scroll host takes focus, which gives Home, End, Page Up and Page Down to the content once it is clicked into, while the `SelectorBar` keeps the arrow keys.
- Demo: the Colors page Layer on Acrylic example composites its layer over the acrylic base fallback rather than over the page card, the surface the Gallery puts under it; the accent and text-control-border tiles take a foreground that is white in both themes, as the Gallery's own do; and the copy button shows the Gallery's success cue (checkmark glyph plus a copied tooltip) instead of copying silently.
- Demo: every gallery page is a `Page` rather than a `UserControl`, matching the WinUI Gallery's own pages. WPF only lets a `Window` or a `Frame` parent a `Page`, so the shell hosts them in a `Frame` inside `NavigationView.Content` with its navigation chrome hidden; `MainWindow` still owns the back stack and drops the frame's journal after every navigation.
- Demo: the Colors page is a Grid with a locked page header, as the WinUI Gallery Color page is. The header, the intro line, the brush snippet and the `SelectorBar` hold their place and only the section content scrolls, with the scroll area bleeding back through the page content margin so the scrollbar rides the page edge.
- Demo: the Colors page section switcher and the `DemoSampleControl` source viewer are `SelectorBar`s rather than restyled `TabControl`s, and the Colors sections now slide between one another through a `SlideNavigationPresenter`, matching the WinUI Gallery's own Color page and `ControlExample`. The `DemoSelectorBar*` styles and size tokens that stood in for the missing control are gone. The Navigation gallery page gains a `SelectorBar` sample that pairs the two new controls.
- `InfoBar.IsOpen` defaults to `false`, as WinUI's does. A bar declared without it used to show immediately; it is now declared closed and opened when the condition it reports arises. Every bar that should be visible from the start needs `IsOpen="True"`.
- `SlideNavigationTransitionEffect` takes WinUI's own numbers: `FromLeft` stays 1 and `FromRight` moves from 0 to 2, leaving 0 where WinUI has `FromBottom`. The names are unchanged, so only code or XAML that reads or writes the numeric value is affected. Ported WinUI values now map across unchanged, and `FromBottom` can be added later without moving anything.
- `SpinButtonPlacementMode` is `NumberBoxSpinButtonPlacementMode`, `BackdropType` is `WindowBackdropType`, and `CornerPreference` is `WindowCornerPreference`, matching WinUI and the .NET WPF Fluent theme. Values are unchanged, and the properties that carry them keep their names.
- `ContentDialog.Opened`, `ContentDialog.Closed`, `InfoBar.Closed` and `TeachingTip.Closed` are `EventHandler<TArgs>` instead of bare `EventHandler`.
- `TabView.TabCloseRequested` and `TabViewItem.CloseRequested` declare `EventHandler<TabViewTabCloseRequestedEventArgs>`, so a handler reads `e.Tab` and `e.Item` with no cast. This retypes the registered handler delegate, so it breaks an already-compiled consumer binary as well as source that recompiles. Both still bubble as routed events.
- Setting `InfoBar.IsOpen` to `false` in code raises `Closed` with `InfoBarCloseReason.Programmatic`; it previously raised nothing.
- Pressing Escape to dismiss a `TeachingTip` now raises `Closed` with `TeachingTipCloseReason.LightDismiss`, matching WinUI; it previously reported `Programmatic`.
- The resource key `NavigationViewSelectionIndicatorBrush` is `NavigationViewSelectionIndicatorForeground`, WinUI's own name. Like the fourteen keys removed below, this fails silently on a `DynamicResource` reference to the old name: no compile error, the target simply keeps its default at runtime.
- `DebugType` is `portable` for every configuration, replacing `full`. Portable PDBs are supported by every debugger the target frameworks reach, Visual Studio 2019 and later on `net472` included, and are what a symbol package can carry.
- The version is declared once, as `VersionPrefix` and `VersionSuffix` in `Directory.Build.props`. The duplicates in `Fluence.Wpf.csproj` won over that file and are gone, along with the hand-maintained `BuildDate`.
- Demo: `DemoSampleControl` surfaces (sample card, options rail, source expander) are remeasured against the installed WinUI 3 Gallery 2.9.3 at 150% DPI.
- `NumberBox`'s bottom accent focus line is 1.5 dp tall rather than 2 dp. The line sits inside the control border, above the 1 dp stroke rather than over it as `TextBox`'s line does, so at the same height the two together read heavier than the `TextBox` underline.
- `NumberBox` insets each spin button rather than the panel that holds them, as WinUI's template does: `Margin="4"` on the up button and `Margin="0,4,4,4"` on the down button, both stretching to the field height with a `MinWidth` of 32. The panel's own `0,1,2,1` inset is gone, so the buttons sit 4 dp inside the field on every edge instead of 1 dp.
- `NumberBox`'s inline spin buttons are borderless at rest, as WinUI's are. `NumberBox_perf2026.xaml` remaps the spin button's RepeatButton brushes to the text-control button tokens, and `TextControlButtonBorderBrush` is `ControlFillColorTransparent` in every theme, so the buttons read as bare chevrons until hover (`SubtleFillColorSecondary`) or press (`SubtleFillColorTertiary`). Fluence painted `ControlFillColorDefaultBrush` over `ControlElevationBorderBrush` instead, which drew a small bordered button around each chevron.
- `Slider` paints the unfilled part of its track once instead of twice. The track border and the increase repeat button both carried `ControlStrongFillColorDefaultBrush`, and the two partial-alpha layers composited to roughly twice the intended opacity: the unfilled track measured #4A4A4A in light against WinUI's #868686, and #D1D1D1 in dark against #9A9A9A.
- `NavigationViewItem`'s selected pill is 36 dp tall and inset 4 dp on both sides, matching `NavigationViewItemOnLeftMinHeight` and `NavigationViewItemButtonMargin`. The pill was 32 dp and sat 6 dp from the left and 10.7 dp from the right, because the item's 36 dp `MinHeight` had to absorb a `4,2,0,2` margin and a 2 dp transparent border. The shared selection indicator now starts at the pill's left edge, where WinUI puts it, rather than 5 dp inside it.
- A top-level `MenuItem` in a `Menu` renders label only, with WinUI's `MenuBarItemButtonPadding` of 10,4,10,4 and `MenuBarItemMargin` of 4,4,4,4, and the bar takes `MenuBarHeight` as a 40 dp floor. Items previously reused the flyout item template, whose icon, gap, accelerator and chevron columns pushed File, View and Help around 105 dp apart against WinUI's 35. Flyout and submenu items are unchanged.
- `TabViewItem` drops the accent underline under the selected tab, which has no WinUI counterpart, and gains the 1 dp `TabViewItemSeparator` between tabs that WinUI draws, hidden before the first tab and on both sides of the selected one. `TabViewItem.MinHeight` is `TabViewItemMinHeight` (32, was 40), the icon margin is `TabViewItemHeaderIconMargin` and the close button margin is `TabViewItemHeaderCloseMargin`.
- `TabViewItem` takes the rest of WinUI's header metrics: `TabViewItemHeaderFontSize` 12 (was 14), `TabViewItemHeaderPaddingWithCloseButton` 8,3,4,3 (was 12,0,8,0), `TabViewItemHeaderPaddingWithoutCloseButton` 8,3,8,3 when the tab is not closable, and a close button of `TabViewItemHeaderCloseButtonWidth` by `TabViewItemHeaderCloseButtonHeight` (32 by 24, was 20 by 20).
- A `MenuItem` inside a `ContextMenu` or a menu drop-down takes WinUI's own box model: `MenuFlyoutItemMargin` 4,2,4,2 (was 2,1) and `MenuFlyoutItemThemePaddingNarrow` 11,4,11,5 (was a 4,0 inset over a 32 dp floor), which is the padding WinUI applies for pen, mouse and keyboard. The presenter takes `MenuFlyoutPresenterThemePadding` 0,2,0,2 in place of a uniform 2, so the plate no longer insets the items horizontally twice. Top-level menu bar items keep their own `MenuBarItem` metrics.
- The `ComboBox` drop-down takes WinUI's item metrics: `ComboBoxItemThemePadding` 11,5,11,7 (was 12,8), the item plate carries WinUI's own 5,2,5,2 margin and `ComboBoxItemCornerRadius` 3 (was 4), and the selection pill is `ComboBoxItemPillWidth` 3 at `ComboBoxItemPillCornerRadius` 1.5 (was 3.5 at 2), matching the `ListView` pill the library already shipped. `MaxDropDownHeight` is 504 (was 480) and the drop-down's vertical inset comes from `ComboBoxDropdownContentMargin` 0,4 on the items presenter rather than a uniform 4 on the scroll host.
- `ContentDialog` takes `ContentDialogMaxHeight` 756, and `TeachingTip` takes `TeachingTipMinHeight` 40 and `TeachingTipMaxHeight` 520. All three limits were absent, so a long dialog or tip grew without bound.
- The submenu chevron on a `MenuItem` is WinUI's `E974` in place of `E76C`, the glyph the `RadioMenuFlyoutItem` template uses; the checkmark drops from 14 to WinUI's 12; and the keyboard accelerator text sits 24 dp from the label rather than 16. The menu separator's full-bleed margin follows the item margin to -4,1,-4,1, which is `MenuFlyoutSeparatorThemePadding` verbatim now that the item margin is WinUI's own value.
- `ToolTip` takes the acrylic surface fallback rather than `SolidBackgroundFillColorTertiaryBrush`, matching `ContextMenu` and `FlyoutPresenter`. WinUI defines `AcrylicInAppFillColorDefaultBrush` and `AcrylicBackgroundFillColorDefaultBrush` with identical tint, opacity and fallback in every theme, so the published key is the right stand-in. The light theme is unchanged at #F9F9F9; the dark theme moves from #282828 to #2C2C2C.
- The `DatePicker` and `TimePicker` flyouts accept with WinUI's `E8FB`, not `E73E`, and both flyout buttons draw their glyph at 16 rather than 12.
- `TeachingTip`'s alternate close button is `TeachingTipAlternateCloseButtonSize` 40 square with a 16 glyph, up from 24 square with a 12 glyph.
- The `CommandBarFlyout` overflow list caps at WinUI's `MaxWidth` of 440 so a long command label no longer widens the whole bar.
- `NavigationView` draws WinUI's divider between the scrolling menu items and the pane footer (`VisualItemsSeparator`, at `NavigationViewItemSeparatorMargin` 0,3,0,4), so a footer entry such as Settings reads as its own region rather than as one more menu item. It stretches the pane width instead of taking the item separator's 12 dp left inset, and it is drawn only when the footer holds something, which is pinned footer menu items, free-form `PaneFooter` content, or both. WinUI reveals it only while the menu list overflows; `docs/winui-parity.md` records the difference.
- `NavigationView`'s pane footer no longer carries an 8 dp bottom inset, so the last footer entry sits at the foot of the pane as WinUI's does.
- `NavigationView`'s open left pane is symmetric. Its items scroller and its footer each carried a right-only 8 dp gutter reserving room for the overlay scrollbar, so every entry sat 4 dp from the pane's left edge and 12 from the right and a selected pill read as off-centre. Both gutters are gone and the rail rides over the items, which is what WinUI does. The footer divider also moved out of the footer container into a pane row of its own, so the footer's inset no longer stops it short of the pane's right edge; WinUI keeps its own separator a sibling of the footer for the same reason.
- High contrast neutralises every `InfoBar` severity background. `SystemFillColorAttentionBackgroundBrush` and `SystemFillColorSolidAttentionBackgroundBrush` resolved to the system highlight while their three siblings resolved to the window colour, so an Informational bar painted highlight behind window text. WinUI maps all of them to the window colour in high contrast, where the severity reads from the icon and the border instead of a coloured plate.
- `InfoBar`'s title no longer combines wrapping with character ellipsis. WinUI wraps and does not trim, and the two together only ever trimmed the last line of an already wrapped title.
- `NavigationViewItem`'s content grid takes WinUI's 14 dip right inset, and the badge presenter drops the margin that was standing in for it, so a badge sits where WinUI puts it relative to the pill's edge. The inset is for the open pane only: a closed pane and Top mode zero it, as WinUI does, because on a 48 dip rail it would eat into the 40 dip icon column and clip every glyph.
- `NavigationViewItem`'s `InfoBadge` floats over the item's top right corner in Top pane mode rather than widening the item, which is what WinUI's top pane presenter does with its -16,0,2,13 margin. A badged and an un-badged item in the same row now measure the same, so the selection indicator no longer re-centres under the wider one.
- `InfoBadge` is never narrower than it is tall, and its corner radius follows its measured height rather than a literal 8. WinUI squares the badge up in `MeasureOverride` and recomputes the radius on every size change; without both, WinUI's own 4 dip minimum width left a single digit badge as a squashed oval. A `CornerRadius` set by the consumer is honoured as given.
- A custom `InfoBar.Icon` is clamped to 16 by 16, the box WinUI hosts one in. An oversized icon used to inflate the icon column and push the bar taller, which the new 48 dip minimum height made plain.
- A `HyperlinkButton` in `InfoBar`'s action slot pulls its own padding back by WinUI's -12,0,0,0, so the link lines up with the message instead of sitting a button's padding further right.
- `InfoBar` takes its corner radius from `ControlCornerRadius` rather than a literal 4, so an application that retunes the theme's corner radii reaches the bar. The dependency property's own default is unchanged, which is what a bar built in code with no theme applied still gets.
- `InfoBar` lays its title, message and action out on one line while they fit and stacks them when they do not, which is WinUI's `InfoBarPanel` (`InfoBarPanel.cpp`) and the single line bar the WinUI Gallery shows by default. Fluence always stacked them, so that shape was unreachable at any width. The bar also takes WinUI's box model with it: a 48 dip minimum height, `InfoBarContentRootPadding` 16,0,0,0, the icon and close button top aligned at `InfoBarIconMargin` 0,16,14,16 and a 5 dip close inset, and the panel's own per orientation margins.
- `InfoBar` renders its `Content`. The control is a `ContentControl`, so `Content` is its XAML content property, but the template had no presenter bound to it: anything nested in the bar compiled, bound, and drew nothing. The presenter sits under the title and message, as WinUI's `ContentArea` does, and takes the banner row itself when the bar carries neither.
- `InfoBadge.Value` rejects anything below -1 instead of folding it into the dot, which is the one place WinUI actively throws on input. A binding producing a negative count used to render as a dot and hide the mistake.
- `InfoBadge` resolves what to show in WinUI's order: a value wins over an icon, and clearing the value falls back to the icon rather than leaving the badge blank. The order was reversed, and a value set on a badge that already had an icon was dropped. A `FontIcon` now selects WinUI's `FontIcon` state rather than its `Icon` state, which is what the two different icon insets hang off.
- `InfoBadge` is no longer focusable or a tab stop. WPF's `Control` defaults `Focusable` to true where WinUI's does not, so a badge inside a `NavigationViewItem` was Tab reachable and took focus on click.
- `NavigationViewItem`'s `InfoBadge` stays visible on a closed or compact pane, pinned to the item's top right corner over the icon, which is what WinUI's `ClosedCompactAndTopLevelItem` state does with it. Fluence collapsed it, so the badge disappeared in exactly the pane state it exists for: a rail with no labels.
- `InfoBadge`'s value text is no longer clipped or seated low. WinUI's 4,0,4,2 text margin nudges its own digits optically; WPF's line box at 11 dip already fills the 16 dip pill, so the bottom inset arranged the text into 14 and cut it off. The horizontal 4s stay, because they set the capsule's width.
- `NavigationView`'s selection indicator plays WinUI's rubber band instead of sliding out of one item and into the next. It used to fade to nothing over 90 ms, jump the gap, and fade back in over 140 ms, so the part of the journey that would read as travel was the part where it was invisible. It now holds its old position at full opacity and stretches until it spans both items, then its offset and its scale origin snap together at the one third mark so the same stretched bar is anchored at the destination and contracts into it, over 600 ms on WinUI's bezier pair. WinUI drives two per-item indicators through `Offset`, `Scale` and `CenterPoint`; a single pane-level bar reaches the same picture with the scale origin standing in for the centre point.
- The list selection pill fades in over 167 ms on the `0,0,0,1` spline in `ListBox` and `ListView`, the timing WinUI's `ItemContainer` gives it, rather than over a linear 83 ms.

### Fixed

- The automation peers for `SplitButton`, `ToggleSplitButton`, `ToggleSwitch`, `DropDownButton` and `NavigationViewItem` refuse to act on a disabled control: `Invoke`, `Toggle`, `Expand`, `Collapse`, `Select`, `AddToSelection`, `RemoveFromSelection` and `SelectItem` now throw `ElementNotEnabledException` the way the `SetValue` providers and WPF's own peers already did. Input never reaches a disabled control, but a UIA client on the same desktop calls these methods directly, so a host's `IsEnabled` gate on an action (an entitlement, a request in flight, an unmet precondition) could be walked around from another process with no focus and no visual cue: a disabled `SplitButton` raised `Click` and executed its `Command`, a disabled navigation entry could be selected and invoked.
- `FluenceWindow` no longer narrows the `WM_NCLBUTTONUP` wParam with `IntPtr.ToInt32()`. Any process on the desktop can post that message with an arbitrary 64-bit wParam, `ToInt32` throws `OverflowException` past 32 bits, and an exception escaping an `HwndSource` hook terminates the host, so one posted message crashed every shown window. - `DropDownButton.CloseFlyout()`, `SplitButton.CloseFlyout()` (inherited by `ToggleSplitButton`) - the programmatic close affordance for the buttons' object-content flyouts. WinUI's flyout contract is that arbitrary content never dismisses itself; the application calls `Flyout.Hide()` after handling a click inside it. Fluence's `Flyout` property is plain object content hosted in a light-dismiss popup, and `SplitButton` previously exposed no close path at all, so a flyout item's click handler could not close the dropdown. `SplitButtonAutomationPeer.Collapse` now routes through the same method instead of reaching into the template by part name. The demo's DropDownButton, SplitButton, and ToggleSplitButton flyout items now close their dropdown on click through the new method.
- `TextControlElevationBorderFocusedBrush` - the WinUI 3 focused text-control border gradient (both stops at offset 1.0, accent seeded from `SystemAccentColorPrimary`, so Light uses the Dark1 ramp step and Dark uses Light2 exactly as WinUI does; solid live-highlight in High Contrast). The token set for text-control borders is now WinUI-complete and available to consumers.

- `Fluence.Wpf.Controls.LoopingSelectorList`, the WinUI 3 looping selector column, now backs the `DatePicker` and `TimePicker` flyouts. Rows are a fixed `ItemHeight` (40 by default), the viewport is exactly nine rows, and the selected row is always the middle one, so scrolling a column moves its selection and setting the selection scrolls that row under the flyout's new centered accent highlight band (the WinUI `HighlightRect`); the row on the band flips its foreground to `TextOnAccentFillColorPrimaryBrush`. The `DatePicker` day and month columns and the `TimePicker` hour and minute columns wrap endlessly rather than stopping at an end, and the day column re-centers its clamped day when a shorter month rebuilds it. The `DatePicker` year column and the two-value AM/PM column are padded with hidden placeholder rows instead of repeated, matching WinUI's non-looping year selector, so the year stops hard at `MinYear` / `MaxYear` instead of wrapping a step past one bound into the other. Wheel deltas accumulate to whole 120-unit notches before a row is stepped, so a precision touchpad's sub-notch events move one value per physical notch rather than one per event, and a touch pan that settles on a fractional offset snaps to the nearest row when the manipulation completes. Columns scroll in item units with recycling virtualization (a thousand repeats of a band realize only the visible rows), a wheel notch moves exactly one row, arrow keys and Page Up / Page Down scroll, and Home and End are swallowed because a looping column has no first or last value. Row hover visuals are suppressed for the duration of a scroll, so rows sliding under a stationary pointer do not flicker. Rows are tab stops carrying the shared `DefaultCollectionFocusVisualStyle`, exactly as `ListBox` rows are, so keyboard focus can reach each column of the flyout and is visible when it lands.
- `BackdropType.Acrylic` now works on Windows 10 build 17063 and later instead of silently downgrading to `None`. Windows 10 has no DWM system backdrop, so `FluenceWindow` applies the undocumented `SetWindowCompositionAttribute` accent policy with `ACCENT_ENABLE_ACRYLICBLURBEHIND`, tinted from the `AcrylicBackgroundFillColorDefault` theme token including its alpha (no extra scaling factor is applied, so a Windows 10 window matches the token every other acrylic surface in the library is drawn from). The tint is resolved on each apply, so a theme change re-tints the window through the existing `ApplyBackdrop` re-run. The path is gated in `WindowPolicy`, which stays pure: `BuildBackdropPlan` and `ResolveEffectiveBackdrop` take the OS transparency-effects setting and the resolved theme, and legacy acrylic is chosen only when neither DWM attribute is available, the build supports the accent state, the Windows "Transparency effects" setting is on, and the theme is not high contrast. `BackdropType.Tabbed` has no legacy equivalent and still resolves to `None` on Windows 10, and every Windows 11 path is unchanged. Moving or resizing the window drops it to the cheaper Aero blur (`ACCENT_ENABLE_BLURBEHIND`) on `WM_ENTERSIZEMOVE` and restores the acrylic on `WM_EXITSIZEMOVE`, because Windows 10 acrylic is recomposited per frame against the desktop behind the window and an undowngraded drag visibly lags the cursor. Swapping away from `Acrylic` writes `ACCENT_DISABLED` explicitly, the analogue of the `DWMSBT_NONE` clear on Windows 11, because the accent policy is sticky on the window handle.

### Changed

- Build: the solution adopts NuGet Central Package Management. `Directory.Packages.props` at the repo root (`ManagePackageVersionsCentrally=true`) is now the single source of truth for every package version; `Directory.Build.props` and all four project files keep `PackageReference Include="..."` without a `Version` attribute.
- `PasswordBox` reveal is now a peek. A read-only, non-focusable overlay paints the revealed text while the native secure field keeps focus, the caret, and the keystrokes, and the behavior empties that overlay the moment the peek ends. The old design swapped in a second editable `TextBox` and pushed the plaintext back into the password box on every keystroke.
- `AutoSuggestBox.MaxSuggestionListHeight` default corrected from 380 to 374, the WinUI `AutoSuggestListMaxHeight` value.
- Demo: the title-bar search is now a real `fluence:AutoSuggestBox` with navigation suggestions - typing filters the pane and opens a suggestion list of matching pages, choosing a suggestion or pressing Enter navigates, and the query button submits. The demo-local `TitleBarSearchBoxStyle` template replacement is deleted; the control renders with the library template.
- `FluenceWindow` draws a single window border. DWM composites its own 1 px border semi-transparently, so a colour written to `DWMWA_BORDER_COLOR` can never match the opaque template border painted inside the client area, and the two coincident borders read as a shade mismatch. On Windows 11 the DWM border is now suppressed with the documented `DWMWA_COLOR_NONE` sentinel, which leaves the rounded corners intact; Windows 10 does not expose the attribute, so nothing is written there and its native frame is unchanged. On every OS the template border is the only one Fluence draws and it is now a 1 dp hairline instead of 2 dp (accent when the window is active and accent borders are on, `CardStrokeColorDefaultSolidBrush` otherwise). Its thickness is plan-driven: `WindowPolicy.BuildFramePlan` returns it and `ApplyFrame` writes it to `BorderThickness`, so the maximized 0-thickness case no longer comes from a template trigger and `BorderThickness` is now shell-managed while the window is shown, exactly as `BorderBrush` already was. `CornerStyle` also drives the template radius now, so a `DoNotRound` or `RoundSmall` window no longer paints the default large radius inside its squared-off or small-radius DWM corners.
- `FluenceWindow` derives its maximized content inset from live system metrics instead of a fixed 6 dp. `UpdateShellMetrics` now reads `SM_CXSIZEFRAME`, `SM_CYSIZEFRAME`, and `SM_CXPADDEDBORDER` through the new `NativeMethods.GetMaximizedFrameMargin`, converts them from device pixels to DIPs, and recomputes on `OnDpiChanged` so a move between monitors of different scale stays correct. The metrics are read at the window's own DPI (`GetSystemMetricsForDpi` paired with `GetDpiForWindow`, both Windows 10 1607 and so below the library's 1809 baseline) rather than at the process system DPI, because under per-monitor v2 awareness `GetSystemMetrics` answers for a different monitor than the one the window is on and dividing its pixels by that window's scale mixes the two DPIs. The invisible resize frame a maximized `WindowChrome` window extends under is exactly that metric sum, so the content now lines up with the work area on every DPI and theme instead of only where the old constant happened to match. A failed metric read (`GetSystemMetrics` reports failure as zero) falls back to the historical 6 dp rather than to no inset.

Fixtures use constructor/`IDisposable` lifecycle instead of `[TestInitialize]`/`[TestCleanup]`, diagnostic probes log through `ITestOutputHelper` instead of `TestContext`, and the non-parallel execution model is preserved via `xunit.runner.json` and an assembly-level `CollectionBehavior(DisableTestParallelization = true)`. The shared `WpfTestSta` STA dispatcher harness is unchanged. Both `net472` and `net10.0-windows10.0.26100.0` pass the full suite.
- Tests: the xunit.v3 port now leverages v3-native features. Repeated per-theme and per-accent `[Fact]` families collapsed into `[Theory]` rows (`ThemeManagerTests`, `ThemeEngineUnitTests`, `AccentRampTests`); environment-gated tests use declarative `SkipUnless` conditions instead of body-level `Assert.Skip` (`AccentRampTests`, `GalleryScreenshotHarness`), letting the `xUnit1004` suppression be removed; manual/maintainer probes are `[Fact(Explicit = true)]`; the shared `WaitUntil` polling helper honours `TestContext.Current.CancellationToken`; and the project runs natively on Microsoft Testing Platform (`UseMicrosoftTestingPlatformRunner` + `TestingPlatformDotnetTestSupport`).
- Text in transparent popups renders with ClearType subpixel anti-aliasing again. A `Popup` with `AllowsTransparency="True"` is a layered window, and WPF silently drops text on a layered surface to grayscale anti-aliasing, which reads as soft or fuzzy at body sizes. The opaque backplate inside each such popup now sets `RenderOptions.ClearTypeHint="Enabled"`, which restores subpixel rendering for that subtree: `ContextMenu` (menu surface and submenu surface), `AutoSuggestBox`, `DatePicker`, `TimePicker`, `DropDownButton`, `SplitButton`, `ToggleSplitButton`, and `FlyoutPresenter`. The `ComboBox` dropdown is deliberately excluded and documented in place, because its `AcrylicBackgroundFillColorDefaultBrush` fill is translucent (alpha `F0`) under a noise overlay and ClearType cannot blend correctly against it. The `FluenceWindow` root is unchanged and stays at the WPF default `Auto` for the same reason.
- Tests: nullable `as`-cast + `Assert.NotNull` pairs (493 sites) replaced with `Assert.IsType<T>(...)` / `Assert.IsAssignableFrom<T>(...)` assignments, so variables are declared non-nullable and CodeQL's "may be null at this access" findings on the old pattern are resolved. `IsAssignableFrom` is used where the runtime type is a subtype of the declared target (base classes, interfaces, and the Fluence `TextBox` template parts).
- Theme engine: a theme or accent apply whose computed output is identical to the last published one no longer rebuilds and republishes the computed dictionary at slot [0]. Windows emits several theme-relevant broadcasts for one user action (`ImmersiveColorSet`, `WM_THEMECHANGED`, `WM_DWMCOLORIZATIONCOLORCHANGED`), and the 100 ms debounce in `SystemThemeWatcher` does not collapse all of them, so every such broadcast used to force a full brush rebuild and a `DynamicResource` re-resolution storm across the whole visual tree. `FluenceThemeEngine.Apply` now fingerprints everything that determines the published output (the resolved theme, the complete computed color map, and the live `SystemColors` members that `SpecialBrushes` reads outside that map) plus the Settings "Transparency effects" flag, which moves no computed color but does decide what a window's backdrop should be, and returns early when the fingerprint matches the last successful publish and that dictionary is still installed at slot [0]. Slot count, slot ordering, and the `BrushFactory` auto-twin behaviour are unchanged; a publish that fails because `Application.Current` is null stores no fingerprint, so the next apply retries. `ApplicationThemeManager.CurrentTheme` and `CurrentBackdrop` still record every request, and `Changed` still fires whenever either the computed dictionary was republished or the requested theme or backdrop moved, so a backdrop-only change is observable without a pointless dictionary rebuild.
- Motion is now disabled under software rendering as well as with the Windows "Show animations in Windows" setting off. `MotionHelper.IsMotionEnabled` additionally requires a hardware rendering tier above 0 (`RenderCapability.Tier >> 16`, since the tier lives in the high word), because on a software-rendered surface every animated frame is a CPU composite and the animation reads as a stutter rather than motion. The `OverrideIsMotionEnabled` test seam still wins over both conditions.
- `PipsPager` scrolls a full run of pips inside a clamped viewport instead of re-rendering a centered window. Every page now gets a pip, and the new `PART_PipsScrollViewer` viewport is clamped along the orientation axis to WinUI's `CalculateScrollViewerSize` length (`defaultPipSize * (visiblePips - 1) + selectedPipSize`, which is `20 * MaxVisiblePips` for the single 20x20 pip box this template uses). The viewport then stays still while the selection moves inside it and slides only far enough to bring a selection that has left it back to the nearest edge, so the pips no longer shuffle under the pointer on every step. The offset animates over the 167 ms `ControlFastAnimationDuration` on the `ControlFastOutSlowInKeySpline` (0,0,0,1) that the pip size morph already rides, and snaps when `MotionHelper.IsMotionEnabled` is false. Because the pips now live inside a `ScrollViewer`, two requests that viewport would otherwise service are taken over by the pager: arrow keys are handled on the pip host so the viewer cannot claim them for line scrolling, and the bring-into-view request a focused pip raises is suppressed so it cannot jump past the pager's own scroll, then re-raised from the viewport itself (WinUI does the same) so an app `ScrollViewer` further out still brings the whole pager on screen. `MaxVisiblePips` therefore bounds what is visible rather than what is realized; pips are realized eagerly rather than virtualized, so the control remains suited to page counts a pip indicator is readable at. Tests: `PipsPager_MaxVisiblePips_WindowsAroundSelectionAsync` pinned the centered re-rendering window that this change removes, so it is replaced by four tests covering full pip realization plus viewport clamping, a stationary offset for in-viewport selection moves, minimal edge scrolling in both directions, and the clamp and offset moving to the vertical axis on an orientation flip (net +3 tests). The pager now also owns the viewport outright: Home and End select the first and last page, Page Up / Page Down are swallowed (the viewer would otherwise page itself and desync the real offset from the pager's target), and an offset change the pager did not write - wheel over a vertical pager, a key that slipped through - is snapped back to the pager-owned target from `ScrollChanged`. Edge-scroll math prefers realized geometry over believed constants: the arranged pip box (a consumer may restyle `PipsPagerPipStyle` away from 20x20) and the viewport the viewer actually got (a parent may arrange the pager narrower than `MaxVisiblePips` boxes), falling back to the theoretical values before first arrange. A page-count change grows or trims the pip run's tail in place instead of tearing down and recreating every pip.
- Light theme: `NavigationViewContentBackground` adjusted from 65% to 66% white (`#A9FFFFFF`). Golden snapshots and the generated `DesignTime.Light.xaml` are updated to match.
- Demo: sample-page right rail restyled - the rail keeps only a 1 px leading separator (no top/right/bottom border), its padding tightens from 24x20 to 16x16, the source-toggle hover border thins to 1 px, and the floating source card shadow softens (blur 2.5, depth 2.5). The rail keeps its 8px top-right corner radius: a WPF `Border` does not clip children, so a square rail corner would overpaint the sample card's rounded top-right arc and its stroke.
- Theme engine: the per-theme `Theme.*.xaml` color tables are parsed once per process and cached (`BaseColorTables`). The tables are compiled, immutable Color-only resources, but the redundant-publish gate needs the color map built before it can decide to skip a duplicate broadcast, so every gated-out broadcast previously still paid a BAML parse and a full table rebuild on the UI thread.
- Demo: page landings in the gallery shell now play the Fluent "page refresh" transition instead of a bare 167 ms fade. The incoming page slides up 150 px while fading in over 300 ms on the 0,0,0,1 decelerating spline (the Fluent page-transition guidance for top-level navigation switches, matching how a WinUI `Frame` lands `NavigationView` content via `EntranceNavigationTransitionInfo`). The transition lands at rest immediately when the Windows "Show animations" setting is off or rendering is software-only, mirroring the library's internal `MotionHelper` gate. The start pose is seeded as a local value before the clocks start (`BeginAnimation` only takes effect on the next animation tick, so an unseeded start let one frame composite at the rest pose and the next snap to the transition start - a visible background flash on every navigation), the clocks hold their end value, and the `Completed` handlers stamp the rest pose and release the clocks in one dispatcher callback so neither end of the transition shows an intermediate frame.
- `NavigationView` Top-mode overflow no longer forces a layout pass, re-measures every item, or rebuilds the overflow menu on each update. `UpdateTopOverflow` reads the width `PART_TopItemsHost` was last arranged at (it is the star-sized column of the pane header grid, so un-collapsing items cannot change it) instead of calling `UpdateLayout()`, which made a `PaneDisplayMode="Top"` resize run a full measure and arrange pass per update on top of the one the resize had already scheduled. Each item's natural width is now cached on the item through an attached property and re-measured only when that item reports a real (non-zero) size change, when its container is cleared, or when a new pane template is applied. The overflow `ContextMenu` and its `MenuItem` children are created once and updated in place, so the click handlers are wired once instead of per pass. An item the previous pass moved into the menu must now clear the fitting limit by a 5px recovery grace before it returns to the strip (WinUI's `m_topNavigationRecoveryGracePeriodWidth`), so a slow drag across an item's threshold no longer flaps it between strip and menu; item placement at a steady width is unchanged. The all-items-fit early exit pays the same grace when the previous pass had anything in the menu, closing the one boundary (a width oscillating a pixel around the exact-fit total) where the last item could still flap. The width cache is also evicted when a measure-affecting property changes on an item that is sitting collapsed in the menu (`NavigationViewItem.OnPropertyChanged`), because a collapsed item is never measured and so never raises the `SizeChanged` that is the ordinary eviction path - shrinking an overflowed item's content now recovers it instead of pinning it in the menu on its stale wider width - while an arrange at the already-cached width (the strip re-arranging a recovered item) no longer evicts anything.
